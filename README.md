# Video to Circle Telegram Bot

Бот для конвертации видео в «кружки» (Video Notes) с системой подписок, проверкой
участия в канале/чате, статистикой и админ-панелью.

## Возможности

- 🎬 **Максимальная поддержка форматов** — mp4, mov, avi, mkv, webm, flv, wmv, 3gp, ts, mts, vob и 30+ других
- 🔄 **Конвертация в кружок** — кадрирование по центру или вписывание с полями, H.264/AAC
- ✂️ **Выбор фрагмента** — начало и длительность через настройки или `/fragment`
- ⏳ **Ограниченная очередь** — позиция при приёме, прогресс кодирования, таймауты
- ♻️ **Повторная выдача** — сохранённый Telegram `file_id`, если исходник и настройки совпадают
- 📨 **Поддержка оплаты** — `/paysupport`, `/terms` и ответ администратора через бота
- 💳 **Подписки Free / Pro** с оплатой через **Telegram Stars** (XTR), включая бессрочную
- 🎥 **Качество на выбор** — Pro-пользователи выбирают разрешение (360/480/640)
- 📦 **Альбомы** — до 3 видео одним сообщением на Free, без ограничений на Pro
- 🎁 **Подарок подписки** — админ выдаёт Pro по ID (`/gift`)
- 🚫 **Отмена подписки** — пользователь сам в меню, админ командой `/revoke`
- 📄 **Экспорт пользователей в CSV** — вся база одной кнопкой
- 🗂 **Карточка пользователя** — тариф, срок, статистика, подарок/снятие Pro
- 🔐 **Проверка подписки** на канал/чат (админы проходят всегда)
- 📈 **Статистика** — пользователи, конвертации, ошибки, время обработки, топ форматов, платежи
- 📋 **Панель задач** — активные конвертации и фоновые задачи бота
- 🌐 **Языки** — русский и английский, переключение в меню
- 👑 **Полноценное меню** — inline-навигация для пользователей и админов
- 💬 **Только личные чаты** — в группах бот не отвечает
- 🐳 **Docker** — готовый к развертыванию образ

## Быстрый старт

```bash
cp config.example.yaml config.yaml
# укажите bot.token и bot.admin_ids в config.yaml
docker compose up -d --build
docker compose logs -f
```

`config.yaml` исключён из Git и Docker build context. В образ копируется только
`config.example.yaml`; рабочий конфиг поступает исключительно через read-only mount.
Если старый образ уже собирался с токеном, его слои не становятся безопасными
после обновления: при публикации такого образа токен нужно перевыпустить через BotFather.

Перед обновлением сделайте резервную копию SQLite штатным механизмом `.backup`
или остановите бот перед копированием файла. Не копируйте открытую БД обычным `cp`
в момент записи. Инструкция по лимитам, local Bot API и проверкам:
[docs/operations.md](docs/operations.md).

Файл обязателен: без него бот не стартует и пишет, что именно не найдено
(раньше молча брались значения по умолчанию, и в логе появлялось
«bot.token не задан» — диагностика уводила не туда). Пути к конфигу и локалям
считаются от расположения `main.py`, поэтому запуск из любого каталога даёт
одинаковый результат.

## Конфигурация

**Единственный источник статических настроек — `config.yaml`** (переменные окружения не используются).
Динамика (подписки, статистика, ссылка на канал) хранится в SQLite (`/app/data/bot_data.db`).

```yaml
bot:
  token: "123456:ABC..."     # токен от @BotFather
  admin_ids: [123456789]     # ID администраторов

default_language: "ru"       # язык новых пользователей (по умолчанию ru)

channel:
  invite_text: "Вступить в канал"

plans:                       # тарифы
  free:
    max_size_mb: 15          # максимальный размер исходного видео (0 = без лимита)
    max_duration_sec: 60     # макс. длительность
    resolutions: [360]       # доступные разрешения кружка
    default_resolution: 360
    crf: 24                  # качество (меньше = лучше)
    preset: "fast"
    daily_limit: 5           # конвертаций в день (0 = без лимита)
    max_album: 3             # видео в одном сообщении (0 = без лимита)
  pro:
    max_size_mb: 0           # 0 = без ограничения: потолок задаёт сам Bot API
    max_duration_sec: 60
    resolutions: [360, 480, 640]
    default_resolution: 480
    crf: 20
    preset: "medium"
    daily_limit: 0
    max_album: 0             # 0 = без ограничения

prices:                      # цены в Telegram Stars (XTR)
  - {code: "pro_30d",  plan: "pro", days: 30, stars: 25}
  - {code: "pro_90d",  plan: "pro", days: 90, stars: 60}
  # lifetime: true — бессрочная подписка (days игнорируется)
  - {code: "pro_life", plan: "pro", days: 0,  stars: 150, lifetime: true}

api:
  base_url: ""              # для local Bot API: http://bot-api:8081
  local: false              # local требует общего каталога файлов

support:                     # лимиты против спама в /paysupport
  cooldown_sec: 120          # пауза между обращениями, сек (0 = без паузы)
  daily_limit: 3             # обращений в сутки (0 = без лимита)

processing:
  workers: 1
  queue_size: 20
  probe_timeout_sec: 15
  encode_timeout_sec: 120
  shutdown_timeout_sec: 30
  temp_dir: "data/tmp"

logging:
  level: "INFO"
```

### Подсказки команд и scope

Список команд в меню «/» хранится на серверах Telegram и задаётся через Bot API.
В BotFather `/setcommands` пишет только **default**-scope: админские команды в нём
увидят все пользователи, а персональный список так не задать вообще. Поэтому списки
публикует сам бот при старте — `command_hints.py`, функция `publish_command_hints`.

Telegram выбирает список по самому конкретному совпадению:

    chat+язык → chat → all_private_chats+язык → all_private_chats → default+язык → default

Список для конкретного чата переопределяет базовый, а личный чат с ботом имеет тот же
ID, что и пользователь, — поэтому `BotCommandScopeChat(chat_id=<admin_id>)` работает
как персональные подсказки для администратора. Что публикуется:

| Scope | Содержимое | Зачем |
|-------|-----------|-------|
| `default` и `all_private_chats` | `USER_COMMANDS` | базовый список для всех |
| `BotCommandScopeChat(admin_id)` | `ADMIN_COMMANDS` | расширенный список каждому админу |

Публикуется по варианту на каждый язык из `i18n.SUPPORTED` плюс запасной список без
`language_code` (он собирается на `default_language` из конфига — для клиентов, чей
язык бот не знает). `default` заполняется вместе с `all_private_chats`, иначе
оставшийся от ручных настроек `all_private_chats` перекрыл бы `default+ru`.
Описания берутся из локалей (`cmd.<имя>`), а `tests/test_command_hints.py` сверяет
списки с реально зарегистрированными `Command(...)` — забытая в списке или лишняя
в нём команда валит тест.

Важно: `language_code` в `setMyCommands` — это язык **клиента** Telegram, а не выбор
пользователя в боте. Пользователь с русским приложением, выбравший в боте испанский,
в меню «/» увидит русские описания. Синхронизировать меню с `/setlanguage` нельзя —
Telegram смотрит только на язык приложения.

Ограничения: `setMyCommands` требует, чтобы бот уже имел этот чат (админ запускал
бота), иначе `chat not found` — такой админ просто пропускается с предупреждением
в логе, остальные публикуются; удалять такие списки нужно явно, `deleteMyCommands`
без scope чистит только базовый; клиент Telegram кэширует меню и показывает старое
до перезапуска приложения.

Ошибка публикации не мешает запуску бота. Если `bot.admin_ids` менялся или админ не
был доступен в момент старта, список обновляется командой `/syncmenu` — она повторяет
публикацию и сообщает, кому применить не удалось. Поскольку BotFather и код пишут в
одно и то же хранилище, меню лучше держать в одном владельце: если списки публикует
бот, в `/setcommands` заходить не нужно — иначе последняя запись затирает предыдущую.

### Описание бота и «о боте»

Два поля, которые Telegram показывает **до** первого сообщения — описание (экран
до `/start`) и «о боте» (профиль бота) — задаются теми же методами, что и в
BotFather: `setMyDescription` и `setMyShortDescription`. BotFather пишет в то же
хранилище, поэтому владелец один — локали (ключи `meta.description` и `meta.about`).
Публикует их `bot_metadata.py`, функция `publish_bot_metadata`, при старте и из
`/syncmenu`. Как и подсказки, это витрина: ошибка публикации не мешает запуску.

Оба поля — **plain text**: `<b>`, `**` и прочая разметка дойдут до пользователя
как обычные символы. Лимиты Bot API — 512 символов на описание и 120 на «о боте»;
более длинный текст Telegram молча обрезает, поэтому тексты из локалей проходят
проверку длины и отсутствия тегов в `tests/test_bot_metadata.py`. Описание написано
по формуле «что я получу» и **не перечисляет ограничения тарифа** — те живут в
`/start` и на экране «💳 Подписка», а описание привлекает выгодами Pro. Публикуется
по варианту на каждый язык из `i18n.SUPPORTED` плюс запасной без `language_code`.

### Форматы ссылок на канал/чат

- `@username` — публичный канал/чат
- `-1001234567890` — числовой ID
- `https://t.me/username` — ссылка на публичный канал/чат
- `https://t.me/c/1234567890` — приватный канал/чат по ID (`-(10**12 + 1234567890)`)

`t.me/c` не приглашает новых участников. Для приватного канала нужна настоящая
ссылка вида `https://t.me/+…` — вторым аргументом `/setchannel` или из `getChat.invite_link`.
Смена канала и его приглашения атомарна; ошибка подтверждающего сообщения не откатывает
уже сохранённую настройку. Ограниченный участник (`restricted`) проходит проверку
только при `is_member=true`.

## Языки

Переводы лежат в `locales/<код>.json`, список языков — `i18n.LANG_NAMES`
(`SUPPORTED` строится из него). Добавить язык:

1. положить `locales/<код>.json` с тем же набором ключей, что и `ru.json`;
2. добавить код и подпись кнопки в `i18n.LANG_NAMES`.

Больше ничего править не нужно: меню «🌐 Язык» строится из `SUPPORTED`,
`default_language` проверяется по этому же списку, а тесты следят за паритетом
ключей, плейсхолдеров и отсутствием дублей текстов.

Сейчас в боте 10 языков: `ru`, `en`, `uk`, `kk`, `uz`, `es`, `de`, `fr`, `pt`, `tr`.
Язык нового пользователя определяется по языку его клиента Telegram
(`i18n.detect_language`: `pt-BR` → `pt`, `uz-Latn` → `uz`); если язык не из списка —
берётся `default_language` из конфига. Сменить язык можно вручную через
`/setlanguage` или кнопкой «🌐 Язык» в настройках, и ручной выбор больше не сбивается.
Для существующих пользователей язык не переопределяется — только при первой регистрации.

## Подписки и оплата

- **Free** — базовое качество (360p), лимит конвертаций в день, до 3 видео одним сообщением.
  Дневной лимит считает только успешные конвертации, сбрасывается в 00:00 UTC
  (03:00 МСК).
- **Pro** — повышенное качество (до 640p на выбор), без лимита по размеру файла
  (потолок остаётся только у Bot API: 20 MB в облачном режиме, без него — с `api.local`),
  без лимита по количеству видео в сообщении и в день.
- **Что именно даёт Pro** показывается числами: экран «💳 Подписка» для Free-пользователя
  выводит построчное сравнение (`plan_copy.pro_benefits`), а `/help` — сводку по обоим
  тарифам (`plan_copy.tariff_summary`). Значения берутся из `config.yaml` и лимита
  Bot API, поэтому текст не расходится с реальными лимитами; строки, где тарифы
  совпадают, не показываются. Free ограничен 15 MB, у Pro лимита по размеру нет —
  через облачный API он превращается в 20 MB, и именно это показывается (в локальном
  режиме — «без ограничений»).
- Оплата — **Telegram Stars**: пользователь выбирает срок в «💳 Подписка», бот
  выставляет счёт (`currency=XTR`). После оплаты подписка активируется, продление
  суммируется к текущей дате окончания. Платежи идемпотентны по `charge_id`
  (повторный `successful_payment` не продлевает подписку второй раз).
  Запись оплаты и выдача прав выполняются одной SQLite-транзакцией; сбой откатывает
  обе операции. Новые счета сохраняют неизменяемые условия и привязку к пользователю.
  Старые 5/6-полевые счета остаются действительны по исходной цене; проверяются XTR
  и фактическая сумма. Параллельные продления сериализуются до чтения срока.
- **Бессрочная подписка** (`lifetime: true`) — дата окончания `9999-12-31`;
  повторная активация её не укорачивает.
- **Подарок** — админ выдаёт Pro через `/gift` или кнопку в карточке пользователя;
  получателю приходит уведомление, источник подписки помечается как `gift`.
- **Отмена подписки** — пользователь может отключить Pro сам («💳 Подписка» →
  «🚫 Отменить подписку», с подтверждением), админ — командой `/revoke <ID>`
  или кнопкой в карточке. Подписка снимается досрочно, остаток срока сгорает,
  звёзды автоматически не возвращаются. Причина отмены пишется в
  `subscriptions.cancel_reason` (`user` / `admin` / `expired`).

## Фоновые задачи

| Задача | Период | Что делает |
|--------|--------|-----------|
| `expire_subscriptions` | 10 мин | Помечает просроченные подписки неактивными |
| `cleanup_temp` | 30 мин | Удаляет только старые каталоги задач этого бота, не активные файлы |
| `daily_stats` | 1 час | Пишет снимок статистики в лог |
| `heartbeat` | 10 сек | Обновляет признак живого event loop после чтения SQLite |

Статус задач виден админу в «📋 Задачи».

```
├── conversion_queue.py  # Ограниченная FIFO-очередь и shutdown
├── request_tracker.py   # Завершение принятых update-хендлеров
├── tempfiles.py         # Изолированные каталоги задач
├── healthcheck.py       # Heartbeat + PID + доступность SQLite
├── tests/               # pytest, включая реальные ffmpeg fixtures
├── pyproject.toml       # Настройки ruff / mypy / pytest
├── requirements.txt
├── requirements-dev.txt # pytest, ruff, mypy (в образ не попадают)
├── Dockerfile
└── docker-compose.yml
```

### Слои

- **`handlers/`** — разбор события, проверки доступа, отрисовка. Тонкие: вызов
  сервиса, ответ пользователю.
- **`services/`** — операции, которые переживут смену интерфейса. Зависят от
  `context`, репозиториев и i18n, но не от роутеров и меню. Например, выдачу
  подписки можно вызвать из скрипта обслуживания:
  `await gift_subscription(ctx, user_id, 30, False)`.
- **`repositories/` / `db.py`** — доступ к данным. Пакет разбит по таблицам,
  `repositories/__init__.py` реэкспортирует всё, поэтому `from repositories import
  UserRepo` работает как раньше.
- **`plans.py` / `access.py`** — правила тарифов и прав.

## Разработка

```bash
python3.12 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt

pytest            # тесты
ruff check .      # линтер + сортировка импортов
mypy .            # проверка типов
```

Инструменты включены в `pyproject.toml`; конфигурация тестов там же
(`asyncio_mode = "auto"` — асинхронные тесты не требуют декораторов).

Что покрыто тестами: локали (паритет, отсутствие мёртвых ключей), тарифы,
платежи, меню (каждая кнопка обрабатывается ровно одним роутером), альбомы,
блокировки, схема БД и миграции, репозитории, сервисы (подписки, экспорт),
конфиг и обработка видео (лимиты, гонка на дневном лимите).

## Миграции и индексы

Схема создаётся идемпотентно (`CREATE TABLE/INDEX IF NOT EXISTS`) — существующая
база обновляется при старте без ручных миграций. Догоняющие миграции (список
`MIGRATIONS` в `db.py`) добавляют недостающие колонки через `ALTER TABLE`.

| Таблица | Индексы |
|---------|---------|
| `users` | `created_at`, `last_seen`, `username` |
| `subscriptions` | `(user_id, active)`, `expires_at`, UNIQUE user_id WHERE active=1 |
| `usage` | `ts`, `user_id`, `(user_id, ts)`, `(status, ts)` |
| `payments` | `user_id`, `ts` |
| `issued_invoices` | `user_id` |
| `conversion_cache` | PRIMARY KEY `cache_key` |
| `support_requests` | `(user_id, ts)` — журнал для лимитов `/paysupport` |

Миграция дубликатов сохраняет историю, оставляет единственную активную запись
с наиболее дальним сроком и не укорачивает бессрочную подписку. Новые колонки
настроек видео и таблицы снимков счетов/кэша добавляются автоматически.

## Формат CSV-экспорта

Разделитель `;`, кодировка `utf-8-sig` (Excel открывает без правки настроек).

`user_id; username; first_name; language; quality; plan; expires_at; created_at; last_seen; conversions_ok; conversions_error`

Бессрочные подписки в колонке `expires_at` помечаются как `lifetime`.
